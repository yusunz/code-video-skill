# 创意简报、文案与场景表（步骤 0–1）

本文件只在步骤 0（简报与文案）和步骤 1（场景拆解）使用。目标是把"一句话主题"变成
"可以直接写代码的镜头清单"，而不是替用户做审美决策。文内数字凡标注"经验值"的，
只用于估算排期与可读性下限，不是硬性规定。

## 1 创意简报模板

| 字段 | 说明 | 示例 |
|---|---|---|
| 一句话主题 | 这条片子只讲一件事 | "把音乐和准确歌词放进代码" |
| 风格 | 视觉方向，可给参考片或关键词；不定就是自由发挥 | "暗色 HUD + 发光粒子" |
| 时长 | 秒数，且必须能换算成整帧 | 15 s @ 30fps = 450 帧 |
| 平台 | 交付去向，影响画幅、时长上限与响度要求 | 横屏视频网站 / 竖屏短视频 |
| 画幅与帧率 | 分辨率 × fps | 1920×1080 / 30fps |
| 情绪 | 观感基调 | 克制、有推进感 |
| 核心信息 | 观众必须记住的 1–3 件事 | 主标题 + 一个数字 |
| 音频 | 用户是否提供音乐、是否提供歌词 | 提供 BGM + 纯文本歌词 |
| 文案授权 | 谁定文案；哪些词必须出现 / 不能出现 | 用户授权自由发挥 |

规则：

- 用户提供歌词时，歌词是**输入**而不是文案素材：不得改写、不得节选替换；要改只能请用户改。
- 用户授权自由发挥 → 你起草后请用户确认；用户没有授权 → 每轮改动都回到用户确认。
- 缺信息先问，一次问清；提问时注明原因（为什么这个字段会改变结果），不要边问边做。
- 时长与帧率定稿后，帧数是硬约束：`总帧数 = 时长(秒) × fps`，必须是整数。

## 2 文案

含叙事、字幕或卡拉 OK 歌词时，先把文案定稿，再拆镜头。

- **标题 / 主文案**：一句话说清，尽量短；先确认是否有必须出现的品牌、域名等要素。
- **解说词**：按语速估算时长——中文口语约 4–5 字/秒，英文约 2.5–3 词/秒（经验值）。
- **字幕**：单行建议不超过约 14–18 个全角字符（经验值，供可读性下限参考）；
  逐字高亮用词级 / 字符级时间戳驱动。
- 文案与音频绑定：每句起止落在拍点或歌词行边界上，而不是"大约每秒一句"。

断句、语感、标点、字体气质属于审美决策，不做规定。

## 3 场景表模板

| # | 起止帧 | 时长 | 一句话主题 | 画面描述（可执行） | 技术选型 | 素材 / 数据 | 音频事件 | 切换方式 |
|---|---|---|---|---|---|---|---|---|
| 1 | 0–74 | 2.5 s | 主题浮现 | 手写标题从粒子中聚拢，线宽随能量变化 | p5 + rough.js | 无 | 0:00 起拍 | — |
| 2 | 75–149 | 2.5 s | 数据推进 | 折线自左向右绘制，末点发光脉冲 | Remotion + SVG | 曲线数据 JSON | 第 1 小节 downbeat | cut |
| 3 | 150–299 | 5.0 s | 副歌高潮 | 粒子星云推近，歌词逐字高亮 | three + DOM | `lyrics.json` | 副歌第 1 行 | 转场（室内→夜空，大幅变动） |

要点：

- 帧区间用半开区间 `[start, end)`；相邻场景首尾相接，不重叠、不留空档。
- **技术选型是参考**（见 `references/capability-map.md`）；同一场景可叠加多层
  （three 背景 + p5 前景 + Remotion DOM 层）。
- "音频事件"列写清这个镜头对齐哪个拍点 / 歌词行 / 音效——这是"音频先行"与画面的接口。
- 秒 → 帧统一用 `Math.round(seconds × fps)`；拍点取自 `audio-analysis.json`，不要手数
  （无音乐场景：对音床补跑 `analyze-music.py`，或直接用 `npm run bed --json` 的网格）。
- **"切换方式"列把"切换"与"转场"分开**：相邻场景边界默认 **cut**（干脆切换）或**几帧微溶解**；
  **转场特效只用在画面场景"大幅变动"的边界**（时间大跳跃、空间大迁移），作用是交代变化、不是装饰。
  大特效另列一份"大特效清单"（出现在哪个边界、什么效果、多长），随分镜表一起给用户过目（有用户在场时）。

## 4 "一句话主题 → 可执行方案"

把抽象描述翻译成**可绘制对象 + 动作 + 时间基准**：

| 抽象说法 | 可执行写法 |
|---|---|
| "回忆涌上心头" | 低频垫音起，p5 粒子从画面底部缓慢上浮，在第 8 小节 downbeat 加速 |
| "数据在说话" | SVG 折线按帧绘制（由 `useCurrentFrame()` 推导），末点脉冲绑定能量包络峰值 |
| "进入太空" | three 相机沿弧线推近，粒子密度随 RMS 能量上升 |

写完自查：如果某行读起来像影评（"震撼""高级感"）而不是指令（画什么、怎么动、何时动），就重写。

## 5 步骤 1 成功门自查

- [ ] 场景表覆盖 `[0, 总帧数)`，无空档、无重叠；
- [ ] 每行都有可执行画面描述 + 明确技术选型 + 素材来源（或"无"）；
- [ ] 音频事件列已与 `audio-analysis.json` / `lyrics.json`（无音乐时与音床网格）对齐
      ——该列在步骤 2 音频分析完成后回填再验（步骤 1 先定画面列与切换方式）；
      呈交分镜确认两种姿势都可行：**已跑完音频链路 → 带音频列一起呈交**；
      **未跑音频 → 先确认"画面列 + 切换方式 + 大特效清单"，回填后再对一次**。
- [ ] 没有任何"待定"。
